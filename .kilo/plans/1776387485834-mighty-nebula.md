# Plan: Build mpv-android on Windows with PowerShell

## Goal
Build the mpv-android Android app on Windows using PowerShell scripts, and generate a release APK.

## Steps

### 1. Create Gradle wrapper for Windows
- Generate `gradlew.bat` using Gradle wrapper task
- Or create manually based on standard Gradle Windows wrapper template

### 2. Convert build scripts to PowerShell
Create the following PowerShell scripts in `buildscripts/`:

| Bash Script | PowerShell Script |
|-------------|-------------------|
| `download.sh` | `download.ps1` |
| `buildall.sh` | `buildall.ps1` |
| `include/path.sh` | `include/path.ps1` |
| `include/download-sdk.sh` | `include/download-sdk.ps1` |
| `include/download-deps.sh` | `include/download-deps.ps1` |
| `include/depinfo.sh` | `include/depinfo.ps1` |
| `include/ci.sh` | `include/ci.ps1` |
| `scripts/*.sh` | `scripts/*.ps1` |

Key conversions needed:
- `#!/bin/bash -e` → `#Requires -Version 5.1`
- `[[ ]]` → `-match` / `if/else`
- `$( cmd )` → `$( cmd )` (PowerShell supports this)
- `source` → `.` (dot sourcing works)
- `${var}` → `$var`
- `${var//-/_}` → `$var.Replace('-','_')`
- `command -v` → `Get-Command -ErrorAction SilentlyContinue`
- `hash` → `Get-Command`
- `printf` → `Write-Host` / `Write-Output`
- `ln -s` → `New-Item -ItemType SymbolicLink`
- `unzip -q` → `Expand-Archive -Force`
- `wget` → `Invoke-WebRequest`
- Environment detection: `OSTYPE` → `$IsWindows` / `$IsMacOS` / `$IsLinux`

### 3. Convert individual build scripts
Convert all scripts in `buildscripts/scripts/`:
- `mpv.sh` → `mpv.ps1`
- `mpv-android.sh` → `mpv-android.ps1`
- `ffmpeg.sh` → `ffmpeg.ps1`
- `libass.sh` → `libass.ps1`
- `libplacebo.sh` → `libplacebo.ps1`
- `dav1d.sh`, `freetype2.sh`, `harfbuzz.sh`, `fribidi.sh`, etc.

### 4. Run build
- Execute download: `.\buildscripts\download.ps1`
- Build dependencies and app: `.\buildscripts\buildall.ps1`
- Assemble release APK: `.\gradlew.bat assembleRelease`

### 5. Output
APK location: `app/build/outputs/apk/release/`

## Notes
- Android SDK/NDK downloads work on Windows
- Most dependencies (meson, ninja, etc.) work on Windows with proper PATH
- Some shell-specific commands (ln -s, sed) need alternatives
- Java/JDK required (Android Studio or standalone)
